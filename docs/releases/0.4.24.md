# Fork 0.4.24 - One-click resync

Use **Mein Fork** and **Aktualisieren und spielen** in your existing launcher.
All players need this complete package. Exit both games normally before updating.
The native network protocol is now version 4.

## New

- **Resync now** in the desync window handles the entire recovery: pause both
  games, save the host world, transfer and verify the save, reload both worlds
  within the running game processes, then compare them.
- Play resumes only after both worlds match. The host's previous game speed is
  preserved, including an intentional pause.
- Progress, error messages and recovery buttons are in English. **Retry** reuses
  an already prepared snapshot. Errors and **Cancel** keep both games paused.
- Unique recovery filenames preserve existing saves. The host world is used;
  client-only changes are discarded.
- Old network packets and build commands cannot cross into the new world.
  Building and previews are blocked during recovery. The desync window closes
  automatically after successful recovery.
- Native regression builds now discover the installed Visual Studio edition and
  allow more time for compiler setup on hosted runners. Version 0.4.23 did not
  reach the launcher because its CI build failed.

## Validation

Local tests with two actual games on build 35924 completed four recoveries,
including clicks from both host and client, an active client construction
preview, correction of a deliberate client-only balance difference, running
simulation and preserved pause. Desync indicators were triggered through the
diagnostic interface for these cases. Road construction after recovery ran in
both worlds, followed by a fresh SYNC result.

A deliberately injected native IPC failure after real save transfer held both
games. Retry successfully reloaded the same snapshot with a new world epoch.
These live tests used the same recovery implementation before the English text
changes. They are developer-observed tests, not player-reported results.

Automated checks cover Lua 5.2, the recovery barrier, snapshots, runtime, actual
UDP lobby transfer with simulated engines, native network epochs and native IPC.
The release pipeline builds the complete package, extracts and verifies its
contents, then validates downloaded assets and hashes before publication.

## Known limitations

- Automatic resync initially supports **two players in a player-hosted lobby**
  on the exact supported Windows game build 35924. Dedicated relays and larger
  groups are not supported. Changing the player roster after recovery starts
  requires a new lobby.
- If recovery cannot succeed, exit both games normally and start a new lobby.
  Cancel does not release the pause.
- The historical Vulkan/Device-lost crash did not occur during repeated local
  reload tests. Rendering during save/load and Vulkan fence handling have been
  guarded, but this does not establish a general fix for that graphics crash.
- Experimental road/track previews from 0.4.21 remain included. Buildings,
  stations, separate terrain tools and upgrades are not covered. Connection
  details and stationary terrain previews retain the limitations documented in
  0.4.22; more mod, bridge and tunnel testing is still needed.

Previous releases remain available.
