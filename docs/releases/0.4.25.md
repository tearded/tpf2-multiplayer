# Fork 0.4.25 - Compact resync and durable log consent

Use **Mein Fork** and **Aktualisieren und spielen** in the existing launcher.
Exit both games normally before updating. All players need this package.

## New

- The native resync progress panel is compact, so it no longer covers more of
  the game than necessary while saving, transferring, loading or checking.
- The duplicate Lua resync window stays hidden while native recovery progress
  is active. The native panel remains the single progress view.
- An unanswered desync-log question is kept for the current lobby session and
  returns after a world reload. Reloading never grants upload consent by itself.
- `Always send`, `Only this once` and `Never` remain explicit choices. A stale
  lobby session is discarded and a second upload in one session is refused.

## Validation

- Lua 5.2 producer, recovery barrier, snapshot, runtime and UDP lobby tests
  passed.
- New regression covers consent persistence across resync, no implicit upload,
  failed IPC retry, stale-session cleanup and duplicate prevention.
- The native menu DLL builds successfully with MSVC; production recovery panel
  states render successfully in the offline renderer.

## Known limitations

- Automatic resync still supports two players in a player-hosted lobby on the
  supported Windows game build 35924. Dedicated relays and larger groups are
  not supported.
- Log upload still waits for the lobby's background report worker and can fail
  when the report endpoint is unavailable.
- The historical Vulkan/Device-lost crash remains an open limitation.

Previous releases remain available.
