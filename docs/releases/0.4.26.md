# Fork 0.4.26 - Resync in the Multiplayer window, log prompt repaired

Use **Mein Fork** and **Aktualisieren und spielen** in the existing launcher.
Exit both games normally before updating. All players need this package.

## New

- The Multiplayer window has a Resync section at the top. It appears on a
  desync, offers **Resync now** and reports the phase, failed step and detail
  while the world is held. It shows the window even when Ctrl+Shift+D hid it.
- The separate Lua "Resync now" popup is gone. The native recovery panel no
  longer collapses to a "Multiplayer status" button: it appears for the held
  world, offers **Retry**, **Cancel** and, after a cancel, **Resync now**, and
  disappears when recovery completes.

## Fixed

- The "Desync detected" log prompt never appeared in 0.4.25: its cleanup called
  `os.remove`, which the game's Lua does not provide. It now empties the pending
  file like every other file the mod removes.
- After **Cancel**, the native panel offered only Cancel again and left no way
  to start a new resync. It now offers Resync now.
- The lobby published control files under one shared temporary name; a second
  writer could remove it between write and replace, which stopped a real
  recovery during the transfer step. Temporary names are now unique per writer.
- The native regression tests call their build script by absolute path.

## Validation

- Lua, recovery barrier, snapshot, runtime, real UDP lobby, native UDP epoch,
  native IPC and desync-report regressions pass; the report test now runs with
  the game's cut-down `os` table.
- Two real build-35924 games on one PC, injected checksum faults: desync shown on
  both sides, Resync now from the window, all phases to completion, both worlds
  reloaded in place, SYNC afterwards with speed restored. One run exercised
  Cancel in the native panel and a new Resync now from the cancelled state, and
  the log prompt appeared. These were injected hash faults, not organic desyncs.

## Known limitations

- Automatic resync still supports two players in a player-hosted lobby on the
  supported Windows game build 35924. With three or more players Resync now
  reports that automatic resync is unavailable; recover manually as before.
- While the world is held, the Multiplayer window cannot be clicked; Retry and
  Cancel are only in the native panel.
- Log upload still waits for the lobby's background report worker and can fail
  when the report endpoint is unavailable.
- The historical Vulkan/Device-lost crash remains an open limitation.

Previous releases remain available.
