# Fork 0.4.28 - Official 0.4.22 with host-led multiplayer resync

Use **Mein Fork** and **Aktualisieren und spielen** in the existing launcher.
Close all game instances normally before updating. All participants need this
package. Older releases remain available.

## Changes

- Includes the latest official release at build preparation, upstream 0.4.22
  (`7990a86`), including its shared previews, joining improvements, fixes and
  experimental Natural Town Growth compatibility.
- A single compact Resync panel opens automatically on a detected desync,
  shows progress and errors, and disappears when recovery completes. No
  persistent status button or duplicate Lua Resync section; the ordinary
  Multiplayer dashboard keeps its visibility preference.
- Only the host can start or retry recovery. With two players the host starts
  directly. With three or more, the host requests readiness and each client
  confirms Ready. The host request counts as their confirmation. Recovery begins
  only after everyone confirms; roster changes invalidate the request, and
  retries require fresh confirmations.
- Native transport preserves separate receive, ordering, chunk and ACK state
  for each participant across reloads. Broadcast packets stay pending until
  every recipient acknowledges them. This fixes the loss of a peer after a
  three-player recovery. No additional three-player cap is imposed.

## Validation

- The corresponding local source build passed a live test with three game
  instances: readiness 1/3 -> 2/3 -> 3/3, successful save/transfer/reload,
  both peers still received by every instance, SYNC and zero desyncs afterwards.
  The user confirmed a construction action appeared everywhere; subsequent
  logs showed one applied action per instance and continued synchronization.
- Automated lobby/UDP recovery tests with simulated engines passed for 2, 3,
  5 and 8 participants. Compiled native transport tests cover the same group
  sizes across three world resets, packet reordering, duplicates, per-recipient
  acknowledgements and retransmission. Readiness, runtime and Lua tests pass.
- Release publication is gated on the complete automated build, regression
  suite, MSI payload/metadata validation and a verified download of the draft
  package. The versioned MSI itself is not separately game-tested before release.

## Known limitations

- Recovery requires a player-hosted lobby with matching packages on supported
  Windows game build 35924; dedicated relays do not advertise it. The cohort
  remains fixed during recovery. Wire protocol stays 4.
- Live validation used an injected checksum discrepancy, not organically
  diverged world objects. More than three real games and sustained load remain
  untested; automated group sizes are not a performance guarantee.
- Recovery uses the host world, replacing client-only changes. Failure retains
  the hold; only the host can retry. There is no Cancel button.
- The historical Vulkan/device-lost crash during reload remains a known risk.
- Natural Town Growth compatibility and building previews retain their upstream
  experimental status. Natural Environment was disabled for the local test;
  this package does not change users' mod selections.
