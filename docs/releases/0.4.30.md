# Fork 0.4.30 - Map pings, camera navigation and repeated desync reports

Update with **Mein Fork -> Aktualisieren und spielen** in the existing launcher.
Close all game instances normally before updating. All players should use this
package. Older releases remain available.

## Changes

- **Ctrl+Shift+P** marks the terrain under your mouse for ten seconds, in your
  player colour. Each player can keep one marker; new pings replace their old
  marker, with a one-second cooldown. The Multiplayer window also offers
  **Here! Ping view centre**.
- **Go to ping A/B/...** jumps to a player's marker while retaining your own
  zoom and orientation. **Go to A/B/...** copies their latest camera view once.
  Incoming pings never move the camera automatically. Expired positions and
  recovery disable navigation. These are cosmetic features, outside world
  commands and save state.
- A new desync after resync can ask for logs again in the same lobby. Consent
  and upload deduplication now distinguish loaded worlds. **Only this once**
  stays limited to the original world; **Always** and **Never** remain saved.
  An unanswered older prompt retains its original world, and a failed backend
  upload does not consume that world's upload allowance.
- Includes the previous 0.4.28 host-led multiplayer recovery and upstream
  0.4.22 content. No dedicated service deployment is needed for these changes.

## Validation

- Real navigation Lua exercised in separate simulated GUI/engine states with
  different clocks: UI callbacks, multiple peers, packet loss, ordering,
  duplicates, marker expiry, malformed/stale/partial data, PID checks, recovery,
  write retries and the real network dispatcher.
- Repeated-desync consent and backend deduplication tests passed, with uploads
  mocked. Existing recovery Lua and preview regressions passed.
- Publication requires the complete CI build, regression suite, MSI metadata
  and payload checks, and a download/hash check of the draft release.

## Known limitations

- Navigation and this log fix have not yet been tested in a real game. The
  shortcut, marker appearance and camera API calls still need live validation.
  Automated simulations are not a live gameplay or performance guarantee.
- Camera presence updates roughly twice a second, subject to simulation/network
  delays. Camera distance is limited to 4000; a farther modded view is clamped.
- Existing 0.4.28 limitations remain: host-world recovery replaces client-only
  changes, a failed recovery retains its hold, Vulkan/device-lost reload crashes
  remain possible, and upstream town-growth compatibility/build previews retain
  their experimental status.
