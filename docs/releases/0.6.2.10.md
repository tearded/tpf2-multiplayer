# 0.6.2.10 — the last speed click wins

## Changed

- Speed: the last click wins. Any player's speed button, in the game's clock, by
  the Tab key or in the Multiplayer window's speed row, sets the session speed
  for everyone, and only the game's own speeds 1x, 2x and 4x can be chosen. No
  more fractional speeds and no averaging of votes. The window's row offers
  1x / 2x / 4x and slower / faster and shows whose click set the speed.
- Pausing is still the host's alone: a joiner's pause key or button does nothing.
- `/speed` in the chat still overrides until the next click.
- Upstream's vote average stays in the code as `K.SPEED_MODE = "vote"`
  (lockstep.lua); the fork ships `"last"`.

Everything from 0.6.2.9 (upstream 0.6.1.9 merged, turned wagons stay turned) is
included; see docs/releases/0.6.2.9.md.

## Validation and known limitations

Offline: the speed vote test has a section for the new mode (a click snaps to
a lever; the newest click among the players counted wins, older clicks stamped
late do not; a silent player stops counting; the leader runs the session at a
lever with no fraction file). The whole logic regression group and luacheck
pass. A live read-only check on 2026-09-20 showed the Tab and pause keys
reaching the slice through the same clock path as the buttons (`SPEEDBTN ...
button`), so keys and buttons behave the same. No joint game test has been made
yet. What to check together:

- A joiner presses Tab or 2x: every game runs at that speed; the window's row
  names the joiner's click. The host presses 4x: 4x everywhere.
- A joiner presses pause: nothing happens. The host presses pause: everyone
  stops; the host's play resumes at the last clicked speed.
- The 0.6.2.9 items are still open: a train bought with a turned car (an ICE)
  looks the same on every instance; quick line edits make no duplicate stops;
  "New line" opens at once; station street connections, stopping a train,
  drawing fences.

The known refund, hot-join, recovery-hold, depot, line-stop and audio
limitations from earlier releases remain, as does the refused peer track split
from the 2026-09-19 session.

The release workflow runs regressions, builds and validates the complete MSI,
and verifies the uploaded download and SHA-256 before publication.

Close games normally, then update every participant through the existing launcher:
**Mein Fork → Aktualisieren und spielen**, version **0.6.2.10**. All participants
need this version: the leader counts the clicks, and every game applies them.
