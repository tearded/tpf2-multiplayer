# 0.6.2.4 — fix ScriptSave crash while loading

Fixes a loading regression introduced by the action sounds in 0.6.2.2. The sound
module saved a different lifetime token in each Lua instance, violating the game's
startup comparison of its two internal ScriptSave states. Initial audio state is
now deterministic, and loading preserves saved audio state for subsequent saves.
The GUI silently adopts historical events instead of replaying old confirmations.

## Validation and known limitations

The regression test fails on the previous implementation and passes with this fix.
It covers independent initial states, save/load equality, legacy audio tokens,
silent reload, recovery and existing purchase/line-assignment sound callbacks.
The release workflow runs regression tests, builds and validates the full MSI,
then verifies the uploaded package download and SHA-256 before publication.

The reported save has not yet been loaded in the actual game with this fix.
Audible and multiplayer verification remain pending. Train-name desyncs and
separate refund/balance discrepancies remain open; the depot and automatic stop
selection test limitations described in 0.6.2.2 still apply.
