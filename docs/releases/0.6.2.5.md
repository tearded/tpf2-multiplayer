# 0.6.2.5 — road ownership and Snowball Fences

Road ownership now uses the engine's typed PlayerOwned component. The previous
Lua table was silently discarded, leaving roads without the intended ownership
and without the blue marking in the ownership tool. Split edges and unchanged
bridge segments also retain their owners through the typed component.

Snowball Fences placements now feed the installed mod's original segment planner.
Start and finish points do not leave cursor constructions behind. Confirmed
fences and hedges, including curves, arcs and decorative bushes, travel as
synchronized model geometry. Preview builds and demolitions are virtualized;
the preview uses cosmetic 3D rendering, or an outline when unavailable. Workshop
files are unchanged. Segment builds preserve the selected collision mode and
do not gather buildings, fields or replace existing constructions.

## Validation and known limitations

Automated tests cover the ownership API contract, crossing/bridge preservation,
Fences capture and network encoding, different local company player IDs, preview
cleanup, private decorative randomness, errors and solo behavior. The Fences
tests also passed locally with the installed Workshop mod's actual planner.
Read-only live API probes verified typed ownership and conversion of a ten-model
fence proposal; the fence command was not submitted to the running game.

The complete multiplayer build, ownership highlighting and Fences dragging have
not yet been verified in a joint game test. Segments are limited to 512 generated
models. Existing roads are not retroactively assigned an owner: use the ownership
tool after updating. All participants need this version for the new FENCE command.

Previously reported train-name desyncs, refund/balance discrepancies and the native
crash while joining a lobby from an already running world remain unresolved.
The depot, automatic line-stop selection and audio test limitations from earlier
releases still apply. This release does not claim to fix those separate issues.

The release workflow runs regressions, builds and validates the complete MSI,
and verifies the uploaded download and SHA-256 before publication.
