# 0.6.2.7 — vehicle stop/go, whole fences, recycled entity ids

Stopping a vehicle now happens on every instance. The vehicle window's stop/go
toggle (the engine's SetUserStopped command) was neither captured by the native
hook nor replicated by the mod: the train halted on the clicking game only and
kept running on the peers, and the vehicle position check raised a desync one
stamp later. The native hook now captures the toggle (its factory has exactly
SendToDepot's shape in the supported build), cancels the click and ships it as
`VSTOP`; every instance, the originator included, applies the new state at the
same command stamp, as for send-to-depot and reverse. The state travels as an
absolute value, so a duplicate is harmless. As with reverse, the button in the
window follows a moment after the click, when the replay lands.

Snowball Fences drags now build whole. Only the first segment of a drag was
built; every following segment was refused with "Kollision" on every instance,
because it touches the segment before it and the replay built with error
checking, unlike the mod's own build call. Segments are now built the way the
installed mod builds them. A refused segment's engine messages are logged.

Bulldozing a fence segment no longer produces phantom edits. The engine reuses
entity ids; after a strict demolish, a segment's record lived on because the
next segment 4 m away passed the "something is still there" check, the dead id
came back as another entity, and the edit scan shipped an edit with empty
parameters that ended in an engine assertion on every instance. A construction
record now counts as present only while its entity still carries a construction
component of the recorded file; a replacement must stand within 1 m of the
spot; an edit is never shipped for, or applied to, a recycled id. This applies
to every tracked construction, not only fences.

## Validation and known limitations

New Lua 5.2 regressions cover the `VSTOP` capture (own and foreign vehicle,
key and state), the peer apply and the strict originator replay, and the
recycled-id case (edit scan, removal poll with a neighbour, own replay not
echoed, native bulldoze still shipped, replacement on the spot, edit refused
and adopted). The fences regression expects the unchecked build. The complete
logic group passes locally. The stop/go prologue was checked against the
supported game binary with a disassembler, the DLL builds, and the Lua maker
sits in the script-caller block so the replay is not captured again.

None of the three changes has been verified in a joint game test yet. Watch the
log for "VSTOP:" after the stop button, "EXEC FENCE ... success=true" for every
segment of a drag, and a clean SYNC afterwards. A fence in "collision on" mode
is now built through obstacles the way the original mod does. Refund/balance
discrepancies, the native crash while joining a lobby from an already running
world, the recovery hold refusing while a key is held, and the depot, automatic
line-stop selection and audio limitations from earlier releases remain as
before. All participants need this version: the peers need the `VSTOP`
handler and the new slice DLL.

The release workflow runs regressions, builds and validates the complete MSI,
and verifies the uploaded download and SHA-256 before publication.
