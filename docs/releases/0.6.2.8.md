# 0.6.2.8 — station street connections

Stations and depots placed on a road now get their street connected on every
instance, and placements that were refused build again. The native slice hook
welds the construction's street stub onto the road split that the originator
shipped. It told the template's pieces apart from the shipped ones by the
segment's owned flag, which is wrong in two directions: a station's street stub
(bus terminus, tram loop, large rail stations) carries no owned flag, so the
hook saw no template and left the raw stub standing beside the split node; and
the halves of a split player-built road inherit the owned flag, so the hook
mistook the shipped split node for a template node and did nothing. Either way
the split stayed orphaned (the log shows "HEAL(orphaned split ...) rejoined:
false 'Kollision'"), or the engine refused the build ("duplicate base nodes",
"Bau nicht möglich"). In the 2026-09-19 session one of eight station and depot
placements was welded.

The hook now identifies template pieces by index: every segment the template
appended after the shipped ones, as recorded in the construction's
segmentsBefore count. Only a loose template end (touched by exactly one
template segment) is ever re-pointed, so a large station's interior is never
touched. A frozen-node index that names the dropped outer node is remapped to
the shipped split node instead of refusing the weld. The separate modular
station weld uses the same rule and now logs why it refuses a shape.

## Validation and known limitations

The DLL builds; the change is in the native hook only, the Lua side and the
wire format are unchanged. The logic regressions pass unchanged. No joint game
test has been made yet. Watch tpf2_slice.log for "[merge] done" or
"[merge-weld] done" after each station or depot placement, and the game log for
a HEALCHK without "rejoined: false". Place a bus terminus or tram loop on a
road, a depot on a player-built road, and a large rail station with a street
connection, and check the road on every instance.

Track builds shipped by a peer that split an existing track (tunnel halves,
a level crossing with two splits) were refused with critical=true and no
message in the same session; that is a separate open issue. The known
refund, hot-join, recovery-hold, depot, line-stop and audio limitations
from earlier releases remain.

The release workflow runs regressions, builds and validates the complete MSI,
and verifies the uploaded download and SHA-256 before publication.

Close games normally, then update every participant through the existing launcher:
**Mein Fork → Aktualisieren und spielen**, version **0.6.2.8**. All participants
need this version: the weld runs on every instance, including the originator.
