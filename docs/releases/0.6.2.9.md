# 0.6.2.9 — upstream 0.6.1.9 merged, turned wagons stay turned

This release brings the fork onto upstream 0.6.1.9 (silver2127/tpf2-multiplayer,
releases 0.6.1.2 through 0.6.1.9) and adds one fix of its own.

## From upstream (0.6.1.2 to 0.6.1.9)

- Line editing without the wait: adding stops to a line no vehicle runs yet
  applies on your game at once; the other players get it at the stamp. "New line"
  opens on a line made ahead of time in lockstep, named and coloured as your click
  chose. Quick stop clicks no longer put the same station on a line twice: a stop
  is identified by its station, not the platform the engine picked.
- Upgrading the second track of a double track (or any track beside a parallel
  one) no longer fails as a false crossing; an upgrade replaces its edges in place.
- A host loading an earlier save mid-session no longer reads itself as thousands
  of units behind: a world switch starts a new world for every player's bridge.
- Companies survive a save made outside the lobby; the mods round to a joiner goes
  out in batches, packaged off the lobby loop with progress.
- Relay fallback for player-hosted games when the punch cannot work; the lobby
  carries the ISRG roots, so hosting works on a Windows without ISRG Root X2.
- Dedicated server mode (a headless game that hosts, loads and keeps a world up
  by itself, see docs/DEDICATED_SERVER.md) and the Steam Workshop signpost item.
  Neither is used by this fork's launcher channel; they are untested here.

## Fork fix

- Turned wagons stay turned. A train bought with a reversed car (an ICE's tail
  head, a cab car, any wagon flipped in the depot) came out with that car facing
  forward on every instance, the originator's included, because the buy replay
  never carried the part's reversed flag. The native hook now reads the flag
  (VehiclePart+0x04) and it travels with the purchase and with vehicle
  replacements. Vehicles bought before this update keep whatever orientation
  they got; replace them once to fix them.

## Dropped

- The fork's own line-click fix from 2026-09-19 is not in this release. Upstream
  0.6.1.9 removes the wait that caused the duplicate stops, so the fork follows
  upstream there. If stops still double up when you edit a line quickly, report
  it with the game log.

## Validation and known limitations

The native DLLs build; the logic regression group (including upstream's new
tests and the new vehicle_reversed_test) and luacheck pass offline. No joint
game test has been made yet. What to check together:

- Buy an ICE or a train with a cab car: every instance shows the same
  orientation. Replace a vehicle: the same.
- Edit a line quickly (add stops, change a platform): no duplicate stops;
  "New line" opens the editor at once.
- The 0.6.2.8 items are still open: bus terminus, tram loop and depot on a road,
  large station with a street connection ("[merge] done" / "[merge-weld] done"
  in tpf2_slice.log), stopping a train (VSTOP), drawing fences.

Track builds shipped by a peer that split an existing track (tunnel halves, a
level crossing with two splits) were refused with critical=true and no message
in the 2026-09-19 session; that is still open. The known refund, hot-join,
recovery-hold, depot, line-stop and audio limitations from earlier releases
remain.

The release workflow runs regressions, builds and validates the complete MSI,
and verifies the uploaded download and SHA-256 before publication.

need this version: the buy wire format changed, and the upstream line editing
runs on every instance.
